## Intent

A workflow in this repository calls `./.github/workflows/deploy-app.yml` the way an app does, for the example app,
against a throwaway SSH server and no registry push. The server's forced command records what it received; a job
after the call asserts the image reference, the command line, the files of the archive (byte for byte against the
tag) and the names in the rendered `.env.prod`. A broken step of the deploy workflow fails on a pull request here,
not on the first live deploy of an app. Until `@softure-ai/deploy` at the workflow's pinned version is on npm, the
CLI runs from the checkout.

## Constraints

- Exclusively owns `.github/workflows/deploy-app.yml`, the new caller workflow, `tools/deploy/e2e/` and
  `tests/repo/deploy-workflows.test.ts` while it runs. DF-8 (in parallel) changes `init`'s `deploy.sh` template: the
  committed e2e copy of init's output is regenerated by a script, and whichever of the two merges second runs it.
- Production callers must not be able to use the test path: it is refused outside this repository.
- No real deploy, tag, publish or registry push. English-only code, comments and commits. FIRE_TRACKER is read only.
