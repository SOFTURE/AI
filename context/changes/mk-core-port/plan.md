# Plan: mk-core-port

Input: change.md, research.md. Complexity: medium (3 phases).

## Goal

- `softure-marketing <all|voice|record|render|preview|posts> <film> [--config path]` from
  `@softure-ai/marketing-kit` runs FIRE's pipeline (voiceover cache, frame-by-frame recording,
  composition, hyperframes render, post copy) for any project that has a `marketing.config.json`.
- FIRE's `video/**` unit tests (film, timeline, voiceover, compose, posts, site tokens) pass in the
  package, translated to English, with the two FIRE-app dependencies stubbed.
- A fixture film in `examples/fixture/` renders a draft 1080×1920 MP4 locally through the CLI.

**Out of scope:** the `marketing.json` contract and JSON Schema, moving the remaining FIRE constants
into config (MK-2); declarative actions (MK-3); TTS adapters (MK-7); other formats (MK-6);
screenshots (MK-4); OG images (MK-5); a release (MK-8); any change in FIRE_TRACKER.

## Approach

**Starting point:** FIRE runs `tsx video/src/cli.ts` from its repository root; every path hangs off
`ROOT` (`cli.ts:34-35`), colours come from `src/app/globals.css` (`cli.ts:338`), films are TS modules
(`film.ts:70-90`), hyperframes runs through `npx -y hyperframes@0.8.85` (`cli.ts:32`).

**Chosen:** a faithful port file by file into the existing folders, with only three kinds of edits:
English text (Polish copy into `messages/`), paths from a config file instead of `ROOT`, and the two
FIRE-app links stubbed. Rejected: generalising while porting (that is MK-2, and it would leave no
proof the port is faithful); keeping `npx` for hyperframes (the roadmap makes it a dependency).

**Key decisions:**
| Decision | Choice | Why | Source |
| --- | --- | --- | --- |
| Layout | `src/film.ts` (scenario model), `voice/voiceover.ts`, `compose/{timeline,compose,site-tokens}.ts`, `record/record.ts`, `render/{render,preflight,hyperframes}.ts`, `posts/posts.ts`, `config/config.ts`, `cli/*`, `messages/` | the folders `docs/03-marketing-kit.md` already reserves | research |
| Config | `marketing.config.json`, zod strict: `locale` (`pl`/`en`), `brand.name`, `app` (`baseUrl`, `path`, `port`, `startCommand` as an argument array with `{port}`, spawned without a shell in the config folder), `siteCss`, `posts.site`, `paths` (`films`, `voiceover`, `build`, `out`, `fonts`, `sfx`); every path resolved against the config file's folder; `--config` flag, default `./marketing.config.json` | FIRE-shaped, only what `cli.ts` took from `ROOT` plus the Polish-only literals | research |
| Channel codes | local `isChannelCode` (`^[a-z0-9-]+$`, ≤ 20, FIRE's `readChannelTag` rule) | `@softure-ai/analytics` brings db, Next and React | research |
| Site-token test | the "real `globals.css`" case reads `tests/fixtures/globals.css` (a copy of FIRE's shape) | the package has no app stylesheet | research |
| Copy | `messages/{en,pl}.ts`: platform labels, "link in bio", the link lines, the posts title, the persona line (`{name}, {age} lat`); chosen by `locale`; `<html lang>` from `locale` | AGENTS.md: copy only in dictionaries | plan |
| GSAP | dependency `gsap@^3.15.0`; render copies `gsap/dist/gsap.min.js` into the build folder | nothing third-party inside the package | research |
| hyperframes | dependency `hyperframes@0.8.85` (exact); run as `node <pkg>/bin/hyperframes.mjs`; `HYPERFRAMES_NO_TELEMETRY=1` unless set | pinned like FIRE; no opt-in telemetry from a public package | research |
| Browser | `playwright@^1.63.0`; `PLAYWRIGHT_CHROMIUM_PATH` overrides the Chromium | the repo's convention (`examples/next-app/playwright.config.ts:9`) | research |
| Films at runtime | `tsImport` from `tsx/esm/api`, dependency `tsx` | the built CLI is JS; films stay TS as in FIRE | research |
| Error style | ported as is (pure functions throw, the CLI exits with a message; screen guard exit 2) | a 1:1 port; result types come with the config contract | plan |
| Posts command | `posts` writes `posts.md` alone; `render` still writes it too | the roadmap's CLI list | plan |

**Critical details:**
- `voiceoverKey` must stay byte-identical (`{text, voice, model, lang: "pl"}`), or FIRE's paid
  cache (`e5df9dc084ca3d58`) stops matching. A test pins the key of a known input.
- `record.ts` timing (`Math.round((frame + 1) * DT) - Math.round(frame * DT)`, `pauseAt(pageNow + 1000)`)
  is copied unchanged: it is measured behaviour, not style.
- The fixture's SFX and voiceover are generated by ffmpeg at test time; no audio file is committed.

## Phase 1: Package and pure core

**Discipline:** test-after (ported tests are the oracle). **Files:** `tools/marketing-kit/{package.json,tsconfig.json,tsconfig.build.json,README.md}`,
`src/{index.ts,film.ts}`, `src/voice/voiceover.ts`, `src/compose/{timeline,compose,site-tokens}.ts`,
`src/posts/posts.ts`, `src/messages/{en,pl,index}.ts`, their `*.test.ts`, `tests/fixtures/globals.css`, `package-lock.json`.

1. Package shell from `templates/package/`: name `@softure-ai/marketing-kit`, version `0.0.0`, one
   export `.` (`src/index.ts`), `bin: { "softure-marketing": "./dist/cli/main.js" }`, dependencies
   (`gsap`, `hyperframes`, `playwright`, `tsx`, `zod`), `files` without tests; remove the `.gitkeep`s it replaces.
2. Port the pure modules with English comments and messages; `film.ts` gets `isChannelCode`;
   `compose.ts` takes `brandName` and `messages` (locale) as input; `posts.ts` takes `site` and `messages`.
3. Port the six test files (English names, English fixture text); add tests for `isChannelCode`,
   the pinned voiceover key and the English/Polish copy.

**Tests:** every FIRE case; `voiceoverKey` of a fixed input equals the FIRE value; posts in `en` and `pl`;
persona line in both locales; a channel code over 20 characters is refused.

**Done when:**
- Automated: the ported tests pass; `tests/repo/packages.test.ts` passes for the package; Gates green (typecheck, lint, test).

## Phase 2: Recorder, render and CLI

**Discipline:** test-after. **Files:** `src/record/record.ts`, `src/render/{render,preflight,hyperframes}.ts`,
`src/config/config.ts`, `src/cli/{main,options,films,voice,server}.ts`, `tests/{config,options}.test.ts`.

1. `config/config.ts`: `loadMarketingConfig(path)` → validated config with absolute paths; errors name the file and the JSON path.
2. `record/record.ts`: the recorder and Director, with `PLAYWRIGHT_CHROMIUM_PATH`; messages point at the configured films folder.
3. `render/`: ffmpeg steps, asset copy (fonts, sfx from config; GSAP from the dependency), compose, hyperframes; preflight checks ffmpeg and the hyperframes bin.
4. `cli/`: argument parsing (`readOptions(argv)` returns options or an error message), film loading with `tsx`, voice (dry run without `--commit`), server start in the config folder, the six commands.

**Tests:** config paths resolve against the config folder; an unknown key and a wrong type name their path;
options: unknown flag, bad film id, `--commit` with `all`, bad `--today`, bad `--quality`, `--config`, `posts`.

**Done when:**
- Automated: config and options tests pass; `npm run build` emits `dist/cli/main.js` with a shebang; Gates green (typecheck, lint, test).

## Phase 3: Fixture film and the draft MP4

**Discipline:** test-after. **Files:** `examples/fixture/{marketing.config.json,films/fixture-tour.ts,app/index.html,app/serve.mjs,prepare.ts}`,
`tests/render.test.ts`, `README.md`, followups backlog.

1. A static fixture app (a form, a button, a result), a three-beat film that fills, taps and checks the screen.
2. `prepare.ts`: copies the fixture into a temporary folder and generates the voiceover (sine audio
   and evenly spaced word timings under the film's cache key) and the five SFX with ffmpeg.
3. `tests/render.test.ts`, opt-in with `MARKETING_KIT_RENDER=1`: runs `all` through `tsx` and checks
   the MP4 with ffprobe (1080×1920, duration within 0.5 s of the composition) and `posts.md`.
4. README: usage, config, requirements, licences. Followups: a CI job for the render test.

**Tests:** the opt-in render test.

**Done when:**
- Automated: `MARKETING_KIT_RENDER=1` render test passes locally; Gates green (typecheck, lint, test, build).
- Manual: frames extracted with ffmpeg (mid-scene and the last second) show the phone with the fixture app, a caption and the end card.

## Risks and rollback

- A dependency install fails in CI (`sharp`, hyperframes) → the static job shows it on the first push; revert the lockfile and the package.
- The port drifts from FIRE's behaviour → the ported tests and the pinned key catch the pure parts; the fixture render covers record and compose end to end.
- Rollback: the change adds one package and lockfile entries; reverting the merge commit removes it.
