## Intent

Close [issue #1326](https://github.com/SOFTURE/AI/issues/1326): dragging a `ResizeHandle` next to a `SidePanel width`
that holds a long list is slow. Two causes: `onChange` fires on every pointer move, so an app that keeps the width in
React state re-renders the whole screen per move; and `--side-panel-width` is an inherited custom property, so each
change restyles every descendant of the panel.

## Context

Labels: `enhancement`, `pkg: theme-notion`, `adoption`. Package `themes/theme-notion` 0.21.1 (published).
`ResizeHandle` and `SidePanel width` shipped in 0.20/0.21. The adopting app measured ~1.3 s of style recalculation
per 40-step drag that drops to ~30 ms once the variable is registered with `inherits: false`, and worked around the
re-renders by writing the variable on the element itself during the drag.

## Scope

- `page.css` registers `--side-panel-width` with `@property … inherits: false`; a test asserts the compiled sheet
  holds the registration.
- `ResizeHandle liveVariable` (optional): during a drag the handle writes the width to that CSS variable on the
  `controls` element and to its own `aria-valuenow`, and calls `onChange` and `onCommit` once on release. Keys and
  double click are unchanged. `SIDE_PANEL_WIDTH_VARIABLE` names the panel's variable.
- README, gallery notes and CHANGELOG; a minor release (0.22.0); the NOTION · Design System artifact follows.

## Constraints

- Without `liveVariable` the handle behaves exactly as before.
- No change to the panel's layout or classes.

## Notes

- Frame skipped: the issue measures both causes and names the fix.

## Decisions (auto)

- The registration lives in `page.css`, the theme's own page stylesheet that every app imports after `theme.css`
  (README setup). `theme.css` is generated by theme-kit; a registration there would need a kit change for one theme
  variable.
- Other inline variables stay inherited: `--sidebar-width` is read by the sidebar's descendants and is static,
  `--form-grid-rows` and `--skeleton-width` sit on small subtrees and do not change during an interaction.
- The prop is `liveVariable` (a `--` name) rather than a boolean: the handle can drive any column, not only a
  `SidePanel`.
- On release the handle restores the variable and `aria-valuenow` to their pre-drag values before calling `onChange`,
  so React's next render owns the DOM again; an app that does not store the width is not left with a stale width.
- A drag whose `controls` element is missing falls back to the per-move `onChange`.
- Minor release (0.22.0): a new optional prop and export. No package in the repository depends on theme-notion.
