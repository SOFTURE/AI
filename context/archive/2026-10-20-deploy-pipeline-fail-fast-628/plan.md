# Plan: fail fast across a release pipeline, and a deploy preflight (issue #628)

Input: change.md, research.md. Complexity: medium (two workflows changed, one new workflow, the action, one new
example, tests, docs).

`.github/workflows/deploy-release-checks.yml`.

1. Tests first:
   - `deploy-cancel-run.yml`: called only, no inputs, `permissions: {}` at the top, one job `cancel` with

## Phase 2: the preflight (TDD)

Files: tests, `.github/workflows/deploy-app.yml`, `.github/actions/deploy/action.yml`.

1. Tests first:
   - `deploy-app.yml`: input `build` (boolean, default true); the check job refuses `build: false` with
     `deploy: true` or with `prebuilt-image`; the build job runs `if: inputs.build`; new output `sha`, the tag's
     commit from the branch guard step;
   - action: input `preflight` (default false); the release step refuses it unless `send`, `verify` and `report`
     are false; the server files, Node and the render run for send or preflight; a new step "Check the SSH secrets"
     (send or preflight, before pack) refuses a missing value by name, a host or user that is not one, a key
     `ssh-keygen -y` cannot read, and known hosts without an entry for the host (`[host]:port` off 22), and makes no
     connection; it runs under bash with fake `ssh-keygen` in the tests (and the real one when present).
2. Workflow and action. The cleanup step already removes `.env.prod`, the key and the known hosts.

- actionlint 1.7.12 over the changed workflows and examples, when it can be fetched.

## Decisions (auto)

- Watchers in the caller, one per part, calling a reusable cancel workflow → the only shape that fires as soon as a
  part ends and keeps `actions: write` out of the checks; one `uses:` line per watcher.
- Split the deploy caller's checks into two calls instead of a cancel inside the checks → no permission change for
  pull request callers; the price is one more `prepare` (seconds) with a tag.
- `fail-fast` opt-in, default false → a pull request still sees every red shard.
- Preflight as a mode of the action, fed by a check-only `deploy-app.yml` call → one validator (the check job), one
  render path (the CLI the deploy uses); no new CLI flag (`env render` into the checkout, deleted by cleanup).
- The SSH check also runs before every send → a bad key fails with a named reason instead of an ssh error, on the
  same code the preflight runs.
- `preflight: true` needs `send`, `verify`, `report` false, spelled out → nothing implicit; the example shows it.
- `init`'s generated `deploy.yml` unchanged → it has no checks or image part to stop; the new example is the pattern.
