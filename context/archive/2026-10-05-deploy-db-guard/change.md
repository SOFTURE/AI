## Intent

Three `softure-deploy` commands that a server deploy script runs around the switch to a new image:

- `softure-deploy backup` writes a `pg_dump` of the production database into a backup folder before the deploy and
  keeps only the newest N dumps (retention).
- `softure-deploy schema-guard` compares the new image's exported migrations (`softure migrate
  --export-migrations`) with the `@softure-ai/db` ledger `softure.migrations` and refuses the deploy when the
  database cannot take them: an applied file edited (checksum), an applied file the image no longer has, or a new
  file numbered below the last applied one (order). It writes nothing.
- `softure-deploy row-counts` counts the rows of a table list the app passes, saves them before the deploy and
  compares after it; a table that lost rows fails the step.

A reviewer can check all three with the package tests on a real Postgres (the CI service and the local server).
