# Research

- `themes/theme-notion/src/tokens.ts`: `textStyles.code` is 13px/20px weight 400 and `fonts.mono` is the system mono
  stack, so the kit's `softure-theme-css` writes `--text-code*` and `--font-mono`: `text-code` and `font-mono` exist as
  utilities. `secondary` (`#f1f1ef` / `#2f2f2f`), `muted` (`#f7f7f5` / `#202020`) and the palette `red` are colours;
  radius `xs` is 3px and `lg` 8px.
- `package.json` `softureTheme.sources` lists `./ui` and `./notion`, so classes in a new `src/notion/*.tsx` are
  generated by the shipped `theme.css` without the app adding `@source`.
- Compositions live in `src/notion/` with one test file each in `tests/notion/` (rendered with `renderToStaticMarkup`,
  classes asserted by regex on `class="…"`). `tests/index.test.ts` checks that no export is `undefined`; it counts
  only `src/ui/` files, so a new part in `src/notion/` does not change its count.
- Existing parts pass `className` through `cn` (tailwind-merge set up by `createThemeCn`), so an app's class wins over
  the part's default (`Status`, `Kbd`).
- A scrollable `<pre>` with `overflow-x-auto` is reachable by keyboard only when it is focusable (axe rule
  `scrollable-region-focusable`); a focusable element needs an accessible name, which the issue's `label` gives.
- README "Components" lists the compositions in one paragraph; CHANGELOG collects entries under the newest heading
  for the next release (0.2.0 is published, so a new `Unreleased` heading is needed).
