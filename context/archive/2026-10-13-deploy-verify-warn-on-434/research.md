# Research: deploy-verify-warn-on-434

Sources: `tools/deploy/src/verify/{schema,checks,run-checks,report}.ts`, their tests, `tools/deploy/scripts/write-schema.ts`,
`tools/deploy/tests/schema.test.ts`, README "verify" section.

- `routeSchema` (schema.ts) is a strict object with `status` (default 200) and `severity` (`fail` | `warn`, default
  `fail`), plus cross-field refinements. `RouteReport` carries `severity` per row; `report.ts` prints a failed row as
  `WARN` when its severity is `warn`, and `isFailure` counts only failed `fail` rows. So a per-response warning is a
  row with `severity: "warn"` and `passed: false`; report and exit code need no change.
- `checkRoute` (run-checks.ts) observes the response, then `checkResponse` (checks.ts) runs status, redirect,
  markers, digest and header checks. The observed status is known before the checks run, so the warn path can
  short-circuit there. A request error (no response) has no status and keeps the route's severity.
- `expandRoute` fetches a `forEach` source and fails the row on any status but 200.
- `schema/deploy.schema.json` is generated by `npm run schema -w @softure-ai/deploy`; `tests/schema.test.ts` checks the
  committed file equals the generated one.
- The body is read only when `needsBody(route)`; on the warn path an unread body is cancelled as today.
