## Answers to unknowns
- **Does `z.toJSONSchema` keep descriptions on keys wrapped in `.default()` and `.prefault()`?** Yes. A probe with zod
  4.6.5 (`node -e "require('zod/package.json').version"`) printed, for `io: "input"`:
  `z.string().describe("A").default("x")` → `{ default: "x", type: "string", description: "A" }`;
  `z.string().default("x").describe("B")` → `{ default: "x", description: "B", type: "string" }`;
  `z.strictObject({...}).prefault({}).describe("C")` and `.describe("D").prefault({})` both keep the description and
  `default: {}`; `.optional()` before or after, `.refine()`, a tuple and an enum with default likewise. A second
  `.describe()` replaces the first (`"H2"`). Discriminated union branches keep the descriptions of their keys
  (`oneOf[i].properties`).
- **Does reuse produce `$defs` that would hide descriptions?** No: the current file has no `$defs`; shared schemas are
  inlined (`grep -c '\$defs' schema/marketing.schema.json` → 0).
- **Which defaults are not in the schema?** Verified in code: beat `pad` 0.35 s (`src/record/record.ts:250`), `tap.after`
  0.35 s (280), `type.perChar` 0.13 s (287), `bring.top` 140 px and `bring.seconds` 0.5 s (270), `wide.scale` 1 and
  `wide.whoosh` false (315-316), `focus.scale` fits the element (307), platform `linkInBio` from
  `DEFAULT_LINK_IN_BIO` (`src/config/config.ts:157`).
