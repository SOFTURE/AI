# Research: deploy-verify-header-starts-with-441

Sources: `tools/deploy/src/verify/{schema,checks}.ts`, their tests, `tools/deploy/scripts/write-schema.ts`,
`tools/deploy/tests/schema.test.ts`, README "verify" section, PR #444 (issue #434).

- `headerChecksSchema` (schema.ts) is a record of lower-case names to `string | string[] | null`; it backs both
  `verify.headers` and a route's `headers`. `HeaderChecks` is inferred from it, so a new item type flows to
  `mergeHeaderChecks` and `checkResponse` through the types.
- `checkResponse` (checks.ts) expands a list into one `checkHeader` per item; `checkHeader` handles `null` (absent)
  and a string (`value.toLowerCase().includes(...)`). An anchored item is one more branch there.
- `fetch`'s `Headers.get` returns the value trimmed of leading and trailing whitespace, so "start of the value" is the
  first non-blank character.
- `schema/deploy.schema.json` is generated by `npm run schema -w @softure-ai/deploy`; `tests/schema.test.ts` checks the
  committed file equals the generated one.
- PR #444 touches `routeSchema` (a new `warnOn` key) and `run-checks.ts`, not `headerChecksSchema` or `checkHeader`;
  the overlap is the generated schema file, README and CHANGELOG, resolved by regenerating and keeping both entries.
